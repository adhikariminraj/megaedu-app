# Changelog

All notable changes to MEGA.EDU are recorded here, in [Keep a Changelog](https://keepachangelog.com/) style (`Added` / `Changed` / `Fixed`), newest first.

**A note on how this file was built**: the git history for this project is a single squashed `Initial commit` — there is no granular commit-by-commit history to generate this changelog from mechanically. What follows is a hand-written reconstruction of the real, verified milestones, grouped by feature area. Where a date is given below, it's inferred from the development session's own context (not a git commit timestamp) and should be read as approximate, not authoritative. **Going forward, add a dated entry here for every notable change** — that's the only way this file stays trustworthy once real commit history exists to lean on instead.

## Unreleased

### Added — Organization Events & Resources (K8, 2026-09-10)
An Organization Admin can now create/edit/deactivate their own Events and create/edit/delete their own Resources, `requireOrgAdmin`-gated, both reusing the already-polymorphic `Event`/`organizationId` and `Resource`/`organizationId` schema (no schema change). Events mirror School Event's own convention exactly — no `DELETE` route, `isActive: false` is the only removal path; Resources get a real hard `DELETE` (no reverse relations, and the first write path `Resource` has had for either owner type). Managed from a new combined "Events & Resources" tab on the Organization Dashboard; active Events and Resources both display on the public `/organizations/[slug]` profile, capped at 5 each, gated only by the page's existing `verified && isActive` guard — never by `academyParticipant`. Explicitly not a full Organization Calendar subsystem — School's Calendar page/projection layer (`src/lib/events.ts`, `CalendarEventForm.tsx`) were untouched.

### Removed — obsolete certificate backfill script (K7, 2026-09-10)
Deleted `prisma/backfill-certificates.ts` — a completed one-time Pass-1 migration script whose target model (`CertificateV2`) was long since renamed to plain `Certificate`, leaving the script permanently broken and responsible for all 13 TypeScript errors this project's verification steps had been citing as a standing "pre-existing, unrelated" baseline. Not referenced by `package.json`, application code, or current certificate documentation. `npx tsc --noEmit` baseline improved from 13 errors to 0.

### Added — Organization logo management (K6, 2026-09-10)
`Organization.logoUrl String?` (nullable, additive), managed via `POST`/`DELETE /api/organizations/[id]/logo`, `requireOrgAdmin`-only — reusing School logo's exact upload infrastructure (`saveUploadedImage`/`deleteUploadedImage`, same validation/replace/delete-ordering) and the existing `Avatar` component's `variant="school"` styling, with no new upload system or Avatar variant. Displayed on the Organization Dashboard, the `/organizations` directory, and `/organizations/[slug]`.

### Changed — public navigation label to "MEGA Academy" (K5, 2026-09-10)
`SiteHeader.tsx`'s `NAV_LINKS` entry for `/courses` now reads "MEGA Academy" instead of "Courses" — a one-line label change, `href`/route/behavior unchanged, driving both the desktop nav and the mobile menu from the same array.

### Added — Course → Provider reciprocal links (K4, 2026-09-10)
The organization/provider name on `/courses`, `/courses/[slug]`, and the homepage's "Explore the Network" course cards now links to `/organizations/[organization.slug]`, completing the reverse direction of the K1 provider-profile journey. Where a card's own course-link and the new provider link would otherwise nest, the card was restructured into a wrapper with two independent links rather than one link wrapping the whole card, to avoid invalid nested `<a>` elements — a technical necessity, not a visual redesign.

### Added — Opportunity edit/delete (K3, 2026-09-10)
`PATCH`/`DELETE` added for both `/api/schools/[id]/opportunities/[opportunityId]` and `/api/organizations/[id]/opportunities/[opportunityId]`, mirroring the existing `Program` route's precedent — explicit field allow-list, ownership re-verified against the URL's school/organization, hard `DELETE` (confirmed safe — `Opportunity` has no reverse relations). `OpportunityPoster.tsx` gained inline edit/delete UI, shared by both School and Organization dashboards.

### Fixed — learner enrollment read authorization (K2A, 2026-09-10)
`/courses/[slug]/learn`'s enrollment lookup previously fell back to an unscoped `{courseId}` filter for any viewer holding neither a Teacher nor a Student profile — dormant while enrollment required one of those profiles, but a live leak of an arbitrary enrollment id the moment that requirement was lifted (see K2 below). Replaced with a `CourseEnrollment.userId`-scoped lookup, the sole authoritative identity for the row.

### Added — global MEGA Academy read-time visibility (K2B, 2026-09-10)
`/courses`, `/courses/[slug]`, and the homepage's course query now all require `published && organization.verified && organization.academyParticipant && organization.isActive` — previously only the write side (publish/enroll) was gated, leaving a course from a since-unverified or non-participating organization publicly visible (though not enrollable) on the read side. `/courses/[slug]/learn` (an already-enrolled learner's own historical access) is deliberately exempt.

### Added — public Organization provider profile (K1, 2026-09-10)
New `/organizations/[slug]` page, mirroring `/schools/[slug]`'s pattern exactly — independently re-verifies `verified && isActive` at the detail-page level, two independent trust badges ("✓ Verified Organization" always; "✓ MEGA Academy Provider" only if `academyParticipant`), published courses shown only when participating, Opportunities shown regardless. `/organizations` now links each card to this profile and shows the same provider badge.

### Added — Co-Scholastic, Kilometer 1: separate evaluation axis, Mark Sheet grading/co-scholastic snapshots, published-result correction fix (2026-09-07)
A product+architecture audit against four real school report-card samples (Rosebud School, Modern Indian School) found the existing scholastic assessment engine already sufficiently flexible for real-world component/weight/scale variation — confirmed by tracing the actual teacher entry UI and admin config wizard, not just the schema — but surfaced three genuine gaps: no model for co-scholastic areas (Work Education, Art, Health & Physical Education, Discipline), no historical freeze for grading criteria on an issued Mark Sheet, and a real UI defect where a published result's correction inputs were permanently disabled, making the already-correct, already-audited backend correction path practically unreachable.

**Co-Scholastic** (`CoScholasticArea`/`CoScholasticPeriod`/`CoScholasticGradeSetting`/`CoScholasticResult`, `src/lib/coScholastic.ts`) — a structurally independent, non-numeric evaluation axis with no calculation engine (grades are ordinal, never aggregated across periods — the annual/final grade is always independently entered, matching real evidence that schools never combine term co-scholastic grades). Grading-scale ownership resolved at `(school, grade, session)`, matching real evidence that the same areas use different scales for different grades within one school. Teacher workflow at `/dashboard/co-scholastic`, deliberately the smaller sibling of the scholastic entry page; config at `/dashboard/co-scholastic-config`.

**Mark Sheet historical snapshot extended** — `MarkSheetGradingBandSnapshot` (frozen grading-criteria table, grouped by scale, closing a real gap where band *wording* remains editable even after numeric values lock) and `MarkSheetCoScholasticResult` (frozen annual co-scholastic grades), both written atomically with the existing subject snapshot at Issue. Verified directly: simulated live edits to both a `GradingScaleBand` and a `CoScholasticResult` after issuance, re-read the already-issued Mark Sheet, confirmed both snapshots completely unaffected.

**Published-result correction UX fixed** (`AssessmentResultsEntryClient.tsx`) — a published cell's inputs now require an explicit "Correct →" action before becoming editable (`PUBLISHED → Correct → editing → Save Correction/Cancel → PUBLISHED`), rather than being permanently disabled. Backend authorization and audit trail unchanged — verified live: a Mathematics Unit Test mark corrected from 6 to 9 for an already-published student, producing exactly one `AssessmentComponentResultAudit` row with the correct before/after values.

**Wizard `gradePoint` gap closed** (`CreateAssessmentSystemWizard.tsx`) — the guided setup's grade-level step previously never collected `gradePoint`, silently producing a GPA-incapable scale; now collects it (optional, with real preset values for the standard-levels shortcut) and sends it to the existing, unmodified grading-scales API.

**Report Card presentation** — co-scholastic section, live grading-criteria table (deliberately *not* frozen — Report Card stays live, unlike Mark Sheet), student photo (`avatarUrl`) and Father's/Mother's Name (`FamilyContact`, both already-existing fields, newly rendered) where present, and a term-side-by-side table layout.

**Locked distinctions preserved, unchanged**: Report Card (live, periodic, correction-reflecting), Mark Sheet (final annual, `Student.id`-keyed, immutable/versioned, no attendance/periodic remarks), Certificate (untouched, its own gaps — school/joint issuance, revocation, verification — explicitly retained on the roadmap as a separate future milestone, not implemented here).

**Verified live**: full teacher evaluation and correction workflow; Co-Scholastic config and entry end-to-end; Report Card rendering of every new section; Mark Sheet issuance/correction with the new snapshots for both a normal student and the userless demo student (`studentMegaIdSnapshot` correctly stays absent); multi-school authorization (a Himalayan Secondary School admin blocked, at both the page and API level, from Sunrise Academy's Co-Scholastic config, entry, and Mark Sheets — using the real school id, not a guessed one). `npx tsc --noEmit` unchanged at the pre-existing 13-error baseline; `prisma/verify-demo-data.ts` passes (two count assertions updated for intentional new seed data and one pre-existing, unrelated seed-script rng() non-determinism, neither a data-integrity issue).

**Deliberately deferred**: any co-scholastic publication/visibility gate; section-scoped roster filtering for Class Teacher entry; PDF generation; all previously-identified Certificate gaps (school/joint issuance, revocation, verification/QR) — retained on the roadmap, not started.

### Added — Mark Sheet, Kilometer 1: formal issued annual result, versioning, GradeHistory placement fix (2026-09-07)
A three-part architecture audit established the product boundary — Report Card (live, periodic) vs. Mark Sheet (issued, immutable, annual) vs. Certificate (separate domain, untouched) — before any schema work began. This kilometer implements the Mark Sheet side of that boundary: two new additive models (`MarkSheet` header + `MarkSheetSubject` snapshot rows), a School-Admin-only Issue/Correct write path (`src/lib/markSheet.ts`), and owner-facing view pages, all reusing the existing assessment calculation engine and Promotion decision workflow **unchanged** — no `FinalAnnualResult` model, no new calculation logic, no new promotion mechanism.

**Phase 0 fix, done first**: `fetchAssessmentResults()`/`buildReportCard()`/`fetchAcademicProgress()` each independently ran an unscoped `GradeHistory` placement lookup with no school filter and no deterministic order — harmless on a live Report Card, unacceptable once a Mark Sheet could freeze the result. Replaced all three with one shared, `schoolId`-scoped `resolveCurrentPlacement()` (`src/lib/gradeHistory.ts`), deterministic by construction (`AcademicSession` already enforces at most one `ACTIVE` row per school). Five downstream call sites updated to pass the `schoolId` they already had in scope. Verified against real two-school seed data with no regression.

**Versioning**: a correction never edits an issued row — it creates a new version and marks the prior one `SUPERSEDED`, linked forward. `@@unique([studentId, academicSessionId, version])` makes a duplicate version physically impossible at the database level (also the concurrency backstop); "only one current version" is enforced via an optimistic-lock `updateMany()`, the same partial-unique-index workaround already used for `AcademicSession`/`TeacherSchoolAffiliation`.

**Identity**: `Student.id`, never `User.id` — verified live end-to-end with a Student holding no `User` account at all (`studentMegaIdSnapshot` correctly left `null`, never fabricated). Snapshot immutability verified directly: issued a Mark Sheet, then simulated both a student rename and a school transfer, and confirmed every frozen field was unaffected.

No PDF, no public verification/QR, no rank/division, no signatory role, no roll number — all deliberately deferred; see [MARK_SHEET.md](MARK_SHEET.md), [KNOWN_GAPS.md](KNOWN_GAPS.md).

**Verified live**: issuance and correction flows exercised through the real UI (School Admin) and the real API routes; Student/Parent access confirmed both positive (own child) and negative (another student, correctly redirected); `npx tsc --noEmit` unchanged at the pre-existing 13-error baseline; existing regression suite (`prisma/verify-demo-data.ts`) passes.

### Added — Calendar, Kilometer 1.1: Day Status, SchoolCalendarEntry, child attribution, Event edit (2026-09-07)
A product-level review of Calendar K1 identified that an event list alone doesn't answer "what kind of day is this?" — this kilometer adds that as an explicitly separate layer, never merged into the existing `CalendarItem` activity projection. New `SchoolCalendarEntry` model: one school-scoped table covering both date-range categories that affect the new Day Status layer (`VACATION`, `EXAMINATION`, `SPECIAL_CLOSURE`) and single-date planned activities that don't (`PTM`, `RESULT_DAY`, `REPORT_CARD_DISTRIBUTION`) — `affectsDayStatus` is derived from `category` entirely server-side, never accepted from the client, so an invalid combination (e.g. a PTM marked as day-status-affecting) is structurally impossible regardless of what the UI sends.

`resolveDayStatuses()` (`src/lib/schoolCalendar.ts`) resolves exactly one dominant status per date from `SchoolCalendarEntry` ranges, `GeneralCalendarEntry` rows where `type === "NATIONAL_HOLIDAY"` only (an `OBSERVANCE` never implies school is closed), and a computed Saturday weekly holiday — via a fixed priority order, never a blended treatment. The Annual view renders this as a restrained cell background (Public Holiday / Vacation / Examination / Weekly Holiday, each visually distinct, Vacation and Examination rendered as a continuous rounded band across their date range) plus a small always-visible legend, layered underneath the existing per-item activity dots/numbers — both layers stay independently readable.

`CalendarItem` gains two optional fields, `childId`/`childName`, populated only by the Parent Calendar's own per-child loop for genuinely per-student sources (Homework, Meetings) — school-wide sources stay attribution-free even for Parents. Fixed a real duplicate-key bug this surfaced: a single Homework row shared by two siblings in the same section now produces two `CalendarItem`s with distinct ids (`Homework:<id>:<childId>`), not one colliding id. Also fixed, as a necessary side effect of adding a third school-wide source to the Parent aggregation loop: Events/Academic Session boundaries/SchoolCalendarEntry are now fetched once per **distinct school** across a Parent's linked children, not once per child — two siblings at the same school no longer double up that school's Events.

`CalendarEventForm.tsx` gained Edit/Deactivate for the school's own Events (using the already-existing `PATCH` route, previously unreachable from any UI); a new `SchoolCalendarManager.tsx` provides the equivalent Create/Edit/Deactivate for `SchoolCalendarEntry`, with a category-adaptive form (a range picker for Vacation/Examination/Special Closure, a single date for PTM/Result Day/Report Card Distribution) — deliberately kept out of the shared `CalendarAnnual`/`CalendarAgenda` display components. Real `CalendarItem.link`s added where (and only where) a genuine destination page exists: Homework → the school's Homework management page (Teacher/Admin), Meetings → `/dashboard/meetings?teacher=<id>` (Teacher/Admin), Result Day/Report Card Distribution → the existing, already-authorized `/dashboard/report-card/[studentId]` (Student's own, Parent's per child).

**Verified live**: server-side category/date validation rejected a PTM given a date range, a client attempt to set `affectsDayStatus:true` on a PTM, an unknown category, and a backwards date range; Teacher blocked (`403`) from both create and edit of `SchoolCalendarEntry`; Saturday + Public Holiday correctly resolves to Public Holiday (not Weekly Holiday); an `OBSERVANCE` General Calendar entry confirmed to produce no Day Status at all; a Vacation and an Examination range both render as one continuous band with correct rounding at the boundaries; a Parent with two children at the same school sees "First PTM"/"Dashain Vacation"/"Mid-Term Examination" exactly once each (not doubled), while a shared Homework row correctly shows as two distinctly-attributed items ("Demo Student — ..." and "Aarav Rana — ..."); Result Day's report-card link resolves (`200`) for the Student's own session; responsive at desktop/tablet/375px mobile, Vacation range remains legible as a continuous band at mobile width. `npx tsc --noEmit` unchanged at the pre-existing 13-error baseline throughout.

**Demo data**: 6 `SchoolCalendarEntry` rows added to `seed-demo.ts`, Sunrise Academy only, clearly fictional (Dashain Vacation, Mid-Term Examination, First/Final PTM, Result Day, Report Card Distribution) — never described as the school's real official dates.

**Deliberately out of scope**: BS↔AD conversion of any kind, Grade/Section/Subject or category filtering on the Admin Calendar, per-school configurable weekly holiday days, blended/dual-color Day Status treatment for overlapping statuses. See [KNOWN_GAPS.md](KNOWN_GAPS.md), [CALENDAR.md](CALENDAR.md).

### Added — Homework, Phase 1: publish, view, today's-due for Parent/Student (2026-09-06)
The fundamental Homework flow: `Teacher → creates Homework → assigns to Grade/Section → selects Subject → publishes → Students see it → Parents see today's due homework for each child`. One new additive model (`Homework`) — deliberately **not** fanned out into a per-student row; Student/Parent visibility is resolved entirely at read time by matching a student's current `GradeHistory` placement against a `Homework` row's own scope, via one shared function (`fetchTodaysHomework()`, `src/lib/homework.ts`) reused by both the Student and Parent dashboard branches — the same "one function, every caller" discipline already established by `fetchAcademicProgress()`.

Authorization reuses `requireTeacherAssignment()` unchanged (no new primitive) — creation is Teacher-only (not composed with `requireSchoolAdmin()`, unlike the analogous `TeachingUnit` route), since `Homework.teacherId` is a real, non-nullable `Teacher` FK and nothing in the approved scope described admin-authored-on-behalf-of-a-teacher homework. Editing/publishing accepts School Admin or the assigned Teacher, re-verified fresh against the homework's own stored scope every time — never "the original creator." The three-way `sectionScopeWhere()` section semantics are unweakened, confirmed live: a teacher holding only section-specific assignments is correctly rejected from creating grade-wide homework.

`dueDate` is date-only, following the `Attendance.date`/`UnitTest.testDate` convention. "Today's Homework" means **due today**, not "published today" — resolved via a new `todayInKathmandu()` helper using `Intl.DateTimeFormat` with an explicit `Asia/Kathmandu` anchor, deliberately not `new Date().toISOString().slice(0, 10)` (the existing Attendance-page convenience-default pattern) — the UTC calendar date diverges from Nepal's actual local date for the first ~5h45m of every Nepal day, precisely the early-morning window a parent checking homework is most likely to hit. Confirmed live across the actual UTC boundary (18:15 UTC = Nepal midnight).

**Verified live end-to-end** through the actual dashboards and direct API calls: DRAFT correctly invisible to both Student and Parent; publish makes it visible to both simultaneously; a Section-B student/parent correctly sees nothing from a Section-A-only item; both sections of a different school correctly see a grade-wide item; publishing freezes `title`/`instructions`/`dueDate`/`sectionId` (`409` on edit attempt); a teacher with only section-specific assignments correctly rejected (`403`) from creating grade-wide homework (confirms the three-way semantics were not weakened); cross-school creation attempts in both directions correctly rejected (`403`) even for an otherwise-legitimate teacher; a forged cross-school `homeworkId` under a different school's own URL correctly rejected (`404`); an ended `TeacherSchoolAffiliation` correctly rejected (`403`); an unrelated Parent account confirmed to have zero visibility into another parent's child or homework; malformed due-date format, a section belonging to the wrong grade, and a `gradeSubjectId` belonging to a different school were all rejected server-side regardless of client input. `npx tsc --noEmit` unchanged at the pre-existing 13-error baseline (all in the unrelated `prisma/backfill-certificates.ts`).

**Deliberately out of scope**, per the approved Phase 1 design: student submissions, file attachments, grading, rubrics, teacher feedback, discussion, plagiarism checking, analytics, reminders/notifications, homework categories beyond the fundamental structure, completion tracking, and upcoming/past homework views (an exact-match `dueDate` query today; a range query later, additive not a redesign). See [KNOWN_GAPS.md](KNOWN_GAPS.md).

### Added — Phase 4D-4: Grades same-URL context migration (2026-09-05)
